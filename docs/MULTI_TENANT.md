# ריבוי לקוחות (Multi-tenant)

פריסה אחת משרתת עסקים רבים. כל עסק מקבל חשבון (אימייל + סיסמה) ונתונים נפרדים לגמרי: פרופיל, פוסטים, תוכניות, קמפיינים, חיבור פייסבוק/אינסטגרם, שימוש וקרדיטים, והעלאות מדיה.

## עקרונות
- **החשבון הראשי (default)** = ROCCA / המפעיל. נשאר בדיוק כמו קודם (שמות המסמכים, קוד הגישה DASHBOARD_TOKEN, משתני Meta ב-env). כניסה עם קוד גישה = מנהל.
- **לקוחות אחרים**: מסמכים תחת `t/<id>/…` במסד; הקול העסקי שלהם נטרלי (לא של ROCCA); רק פייסבוק ואינסטגרם (X/TikTok/אתר משתמשים בפרטי הגישה של המפעיל ולכן מושבתים).
- **Webhooks של Meta** מנותבים לפי מזהה העמוד/אינסטגרם; מזהה לא מוכר — מתעלמים. תשובות אוטומטיות פועלות רק לחשבון הראשי.
- **חיבור פייסבוק**: ה-`state` של OAuth חתום וכולל את החשבון, והחיבור נשמר רק אצלו. מחיקת נתונים מ-Meta מנתקת את החשבונות המתאימים.

## הגדרה
משתנה `SIGNUP_MODE`:
- `closed` (ברירת מחדל) – אין הרשמה, שום דבר לא משתנה בפריסות קיימות.
- `invite` – הרשמה עם קוד הזמנה חד-פעמי (טאב "ניהול" ← "קודי הזמנה").
- `open` – הרשמה חופשית: ניסיון חינם עם 3 פעולות במתנה, בלי כרטיס (ראו BOOL_PLATFORM.md).

## כלי מפעיל (טאב "ניהול", רק עם קוד הגישה)
רשימת לקוחות עם שימוש/עלות, שינוי מסלול, השהיה/הפעלה, מחיקה (כולל כל הנתונים), יצירת קודי הזמנה.

## בדיקות
`npm run tenant-check` (הפרדה מקצה לקצה; עם `TEST_DATABASE_URL` גם מול Postgres), `npm run tenant-unit`, `npm run smoke`, `npm run ui-check`.

## לוגסי גלרי
אפשר לפתוח אותו כלקוח (invite) במקום עותק נפרד — מחליטים לפי המחיר/בידוד שרוצים. העותק הנפרד (`render.lugasi.yaml`) ממשיך לעבוד.
